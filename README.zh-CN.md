## 工程原则

- **快速失败**——绝不让错误悄无声息地被吞掉。
- **修复根因，而非症状**——不在 Bug 上堆叠掩盖问题的补丁。
- **保持可观测**——关键路径应当具备有效的日志、指标和链路追踪。
- **面向调试设计**——重要决策和状态变化应当可解释、可追溯。
- **让文档持续演进**——代码、契约与运维知识必须同步更新。
- **保护主干稳定**——隔离高风险工作，让每次变更都清晰可评审。
